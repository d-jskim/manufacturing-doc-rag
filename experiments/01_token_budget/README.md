# 01 토큰 한도 실험

## 1. 목적

청킹·검색 비교에 공통으로 적용할 문맥 토큰 한도를 데이터로 결정함.

## 2. 설계

- **측정 대상**: 데이터셋의 모든 PDF 페이지 텍스트(pypdf로 추출)
- **토큰 측정 기준**
    - 생성 모델 입력: `o200k_base`. tiktoken이 생성 모델 이름(`gpt-6-luna`)을 인식하지 못하므로 대체 인코딩으로 센 근사값임.
    - 임베딩 입력: `intfloat/multilingual-e5-base`. 실제 입력과 같도록 접두어 `passage: `와 특수 토큰을 포함해 셈.
- **질문**: `development.json` 30개. 질문마다 근거가 걸친 고유 페이지 수를 셈.
- **결정 방식**
    - N(문맥 페이지 수): 근거 페이지 수가 N 이하인 질문이 90% 이상이 되는 가장 작은 값. 근거가 없는 질문은 제외함.
    - 문맥 토큰 한도: 생성 모델 기준 페이지 토큰 수의 p90 × N(올림).

## 3. 예측

| 항목 | 예측 |
| --- | --- |
| 페이지 토큰 중앙값(생성 모델 기준) | 700~900 |
| 임베딩 입력 한도(512) 초과 페이지 비율 | 상당수 |
| N | 2 |
| 문맥 토큰 한도 | 1,600~2,000 |

## 4. 실행

- **사전 조건**: 데이터 준비(`scripts/prepare_dataset.py`)
- **실행**: 저장소 루트에서 `uv run python experiments/01_token_budget/run.py`
    - 설정의 `datasets`를 차례로 실행하며, `--dataset`으로 하나만 실행할 수 있음.
- **결과 파일**: `experiments/01_token_budget/results/{dataset}/e01_c0_p0_r0_{시각}_token_budget.json`
- **보고서**: baseline이 확정된 데이터셋만 `results/{dataset}/report.yaml`을 작성하며, 보고서 화면에 표시됨.

## 5. 결과

### Basic(baseline)

| 항목 | 예측 | 실제 |
| --- | --- | --- |
| 페이지 토큰 중앙값(생성 모델 기준) | 700~900 | 712 |
| 임베딩 입력 한도 초과 페이지 비율 | 상당수 | 83.6%(360쪽 중 301쪽) |
| N | 2 | 2 |
| 문맥 토큰 한도 | 1,600~2,000 | 1,582(p90 791 × 2) |

- 근거 페이지 수 분포: 1쪽 13개, 2쪽 14개, 3쪽 2개, 근거 없음 1개(`M-DEV-24`)
- 재실행(1801)에서 실행 ID 외 모든 값이 1501과 같음을 확인함.

### Intermediate·Advanced(추출 품질 확인 전 측정값)

| 데이터셋 | 페이지 | 페이지 토큰 p90 | 512 초과 비율 | 근거 페이지 수 분포 | N | 한도 |
| --- | --- | --- | --- | --- | --- | --- |
| Intermediate | 3,750 | 738 | 45.1% | 1쪽 10 · 2쪽 15 · 3쪽 5 | 3 | 2,215 |
| Advanced | 18,000 | 712 | 49.6% | 1쪽 8 · 2쪽 12 · 3쪽 7 · 4쪽 2 · 5쪽 1 | 3 | 2,136 |

- 추출 품질을 확인하기 전 값이므로 결정에 사용하지 않음.

## 6. 결론

### Basic

- 문맥 토큰 한도 1,582를 c1·c2·c3에 동일하게 적용함.
- 페이지의 83.6%가 임베딩 입력 한도를 넘으므로, 1페이지 = 1청크(c1)만으로는 페이지 뒷부분이 임베딩에 반영되지 않음. 따라서 c2·c3 비교를 진행함.
- **한계**
    - 근거가 3페이지인 질문 2개는 c1의 문맥에 근거를 모두 담을 수 없음.
    - 생성 모델 토큰 수는 대체 인코딩으로 센 근사값임.

### Intermediate·Advanced

- 결정을 보류함. 해당 데이터셋으로 넘어갈 때 아래 항목을 먼저 확인함.
    - Intermediate: 표의 행·열·단위가 추출 텍스트에 보존되는지
    - Advanced: 근거가 4~5쪽인 질문이 있으므로 "질문의 90%를 담는 N" 기준이 적절한지

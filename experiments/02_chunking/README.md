# 02 청킹 실험

## 1. 목적

c1·c2·c3의 검색 품질을 비교하여, 다음 단계(검색 방식 비교)에 사용할 청킹 방식을 결정함.

## 2. 설계

### 변수: 청킹 방식

| 버전 | 방식 | 크기·overlap |
| --- | --- | --- |
| c1 | 1페이지를 1청크로 사용함(기준선) | 페이지 전체 |
| c2 | 본문 토큰 수 기준으로 재귀 분할하며, 페이지 안에서만 나눔 | 508토큰 이하, overlap 50토큰 |
| c3 | c2와 같으나 페이지 경계를 넘어 나눔 | 508토큰 이하, overlap 50토큰 |

- 508토큰은 임베딩 입력 한도 512토큰에서 접두어와 특수 토큰 4개를 뺀 값임.

### 고정 조건

- **데이터**: `manufacturing_basic`(PDF 15개, 360쪽)
- **질문**: `development.json` 30개 중 참고 근거 문서가 있는 29개를 평가함. 나머지 1개는 해당 없음으로 표시함.
- **임베딩**: m1(`intfloat/multilingual-e5-base`). 질문에는 `query: `, 문서에는 `passage: ` 접두어를 붙임.
- **검색**: r1(임베딩 유사도 검색). 후보 20개를 exact 검색으로 가져옴.
- **문맥 토큰 한도**: 1,582토큰(생성 모델 입력 기준, 01 토큰 한도 실험 결과). 후보를 순위대로 담다가, 다음 청크를 더하면 한도를 넘을 때 멈춤.

### 지표

- **k**: 문맥 한도 안에 들어간 청크 수. 질문마다 기록함.
- **Hit@k**: 참고 근거 문서 중 하나라도 문맥에 있으면 1, 없으면 0.
- **Recall@k**: 문맥에 있는 참고 근거 문서 수 ÷ 전체 참고 근거 문서 수.
    - 두 지표 모두 문서(`book_id`) 단위로 계산하며, 같은 문서의 청크는 한 번만 셈.
- **근거 문장 포함률(보조 지표)**: 근거 문장(`quote`)이 문맥의 청크에 들어 있는 근거 그룹 수 ÷ 전체 근거 그룹 수.
    - 근거 그룹은 답에 필요한 사실 하나를 뜻하며, 그룹 안의 근거 문장 중 하나만 들어 있어도 찾은 것으로 봄.
    - 문서 단위 지표는 같은 문서 안에서 근거가 있는 위치를 찾았는지 구분하지 못하므로 함께 기록함.
- **ANN 비교**: 같은 질문을 근사 검색(ANN)으로도 실행함. exact와 순위가 같은 질문 수, ANN recall(exact 후보 중 ANN도 가져온 비율), 검색 시간을 기록함. 평가 지표는 exact 결과로 계산함.
- **비용**: 단계별 시간, 질문별 검색 시간, 임베딩 입력 토큰 수, 실행 환경(CPU·GPU).

## 3. 가설

- c1은 청크(페이지)의 83.6%가 임베딩 입력 한도 512토큰을 넘으므로, 한도 이후 내용이 임베딩에 반영되지 않아 페이지 뒷부분의 근거를 놓칠 것임.
- c2는 모든 청크가 512토큰 이하이므로 페이지 전체 내용이 임베딩에 반영됨.
- Basic 자료에서는 c2와 c3의 청크 경계가 같고 페이지 표시(`[p.N]`)만 다르므로, 두 방식의 결과 차이는 작을 것임.

## 4. 예측

| 항목 | 예측 | 근거 |
| --- | --- | --- |
| Hit@k(문서 단위) | 세 방식 모두 높고 차이가 작음 | 문서가 15개뿐이라 근거 위치가 아니어도 같은 문서의 청크만 찾으면 정답으로 처리됨 |
| 근거 문장 포함률 | c2가 c1보다 높음 | c1은 페이지 뒷부분이 임베딩에 반영되지 않음 |
| 평균 k | c1 약 2, c2·c3 약 4~5 | 1,582 ÷ 청크 길이(c1 약 640, c2 약 330) |
| c3와 c2의 차이 | 질문 1~2개 이내 | 청크 경계가 같고 페이지 표시만 다름 |
| 근거가 3페이지인 질문 2개 | c1에서 근거 문장 포함률이 1 미만 | c1의 문맥에는 페이지가 최대 2개 들어감 |
| ANN과 exact | 모든 질문에서 순위가 같음 | 청크가 수백 개 수준이라 근사 검색 색인이 만들어지지 않을 것으로 봄 |
